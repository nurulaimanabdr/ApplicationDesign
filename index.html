Phase 01

Setting up the zero page

Create a basic page with a RadioButton and a button, and define the Firestore cart collection.

01
Phase 1 · Page setup

Create a blank test page

  1. Open the Page Selector (the overlapping-squares icon on the left menu).
  2. Click + Add Page.
  3. Skip the templates and click Create Blank in the top-right corner.
  4. Name the page DatabaseTestPage and click Create.

Use a separate test page so you can verify Firestore writes before connecting the full shopping-cart interface.

02
Phase 1 · Page setup

Add the UI widgets

  1. Open the Widget Palette (plus icon on the left).
  2. Find RadioButton and drag it onto the blank page.
  3. Add a Button just below the RadioButton.
  4. Set the button text to Send to Database.

03
Phase 1 · Page setup

Define the radio-button options

  1. Select your RadioButton widget.
  2. In the right-side Properties Panel, find Define Options.
  3. Add three hardcoded test choices: Oat Milk, Almond Milk, and Whole Milk.

The options are fixed for this simple test. Their selected text will be stored as the selected_milk value.

04
Phase 1 · Firestore structure

Configure the Firestore cart schema

In the Firestore tab, create or confirm the cart collection. The original PDF lists the following schema, but this basic test writes only user_ref and selected_milk.

Field nameData typeTest usage
user_refDocument Reference → usersMapped in test
product_refDocument Reference → productsSchema field
selected_milkStringMapped in test
selected_sizeStringSchema field
selected_tempStringSchema field
quantityIntegerSchema field

Important correction: The PDF says “three main collections” but only gives the fields for cart. The users and products names appear as reference targets, not as fully specified schemas. Use just the two mapped fields for the minimal test; the remaining fields are for a fuller cart implementation.

For this test, the button action maps only user_ref and selected_milk. Other listed fields belong to the broader cart schema.

Before testing, make sure Firebase is connected, Firestore is enabled, and your test user has permission to create documents in cart. A matching users record must exist if user_ref is a user-document reference.

Phase 02

The routing bridge

Make sure the test page loads after login so that Firebase has an authenticated user reference.

05
Phase 2 · Authentication

Route the app through login

  1. Open Settings & Integrations (gear icon).
  2. Navigate to App Settings → Authentication.
  3. Set Entry Page to your existing Login/Signup page.
  4. Set Logged In Page to DatabaseTestPage.
Login / Signup  →  Authenticated session  →  DatabaseTestPage

Why login matters: You are setting user_ref from the authenticated user’s document reference. Test with a signed-in account and permitted Firestore access. These routing settings are for the practical; restore your original Logged In Page when finished.

Phase 03

Wiring the action

Connect the button to Firestore and map the current user's reference and the selected radio-button value.

06
Phase 3 · Connect the button

Add the Create Document action

  1. On DatabaseTestPage, select the Send to Database button.
  2. Open the Action Flow Editor and select the button tap action (On Tap).
  3. Click + Add Action.
  4. Choose Backend/Database → Firestore → Create Document.
  5. Set Collection to cart.

07
Phase 3 · Map data

Map the two test fields

  1. Within the Create Document action, click + Add Field.
  2. Add the user reference and the selected-milk field using the settings shown below.

Field 1 · User reference

Field: user_ref

Value source: From Variable

Path: Authenticated User → User Reference

Field 2 · Selected option

Field: selected_milk

Value source: From Variable

Path: Widget State → RadioButton (selected value)

Match your field types: user_ref stores a Firestore document reference, while selected_milk stores the option text.

This is the difference to remember: Here, the value changes depending on which RadioButton option the user selects. In Part 2, each button instead writes a fixed Specific Value.

Phase 04

Execution & verification

Run the test and check that the expected data is saved in the cart collection.

08
Phase 4 · Execute

Run the test in FlutterFlow

  1. Check the top-right Bug icon and resolve any reported configuration errors before testing.
  2. Click the top-right Lightning Bolt icon to start a fresh Test Mode session.
  3. Log in with a test account.
  4. Confirm that the app takes you to DatabaseTestPage.
  5. Choose Oat Milk, Almond Milk, or Whole Milk.
  6. Click Send to Database.

Each successful button press is intended to create a new document in the cart collection.

09
Phase 4 · Verify

Verify the saved document in Firebase

  1. Open the Firebase Console in a new browser tab.
  2. Go to Firestore Database and open the cart collection.
  3. Find the new document created by your test.
  4. Confirm user_ref points to the logged-in user and selected_milk matches the selected radio-button option.

Expected document values (illustrative)

FieldExpected value
user_refReference to the authenticated user's document
selected_milkOat Milk (or your chosen option)

Illustration of expected fields. This is not a captured Firebase record.

Success means the UI choice has been passed into a new Firestore document: frontend-to-backend data binding is working.

Each tap runs Create Document, so repeated taps can create multiple test records. This exercise demonstrates a database write, not a complete shopping-cart update or quantity-management system.
